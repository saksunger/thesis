# Simulated Data

Everything here is **generated** by the MATLAB simulator and **gitignored** — reproducible from seed via `make` targets. Two flavours:

## 1. Phase 1/2 demo outputs (small, illustrative)

| Subfolder                                | Produced by               | Files                                                                                  |
|------------------------------------------|---------------------------|----------------------------------------------------------------------------------------|
| `phase1_demo/`                           | `make demo`               | `phase1_layout.png` (7-cell hex + UE path), `phase1_kpis.png` (RSRP/RSRQ/SINR vs t)    |
| `phase2_demo/`                           | `make demo-ho`            | `phase2_serving.png` (serving cell + HO event markers), `phase2_l3rsrp.png` (L3 RSRP)  |
| `phase2_sweep/`                          | `make sweep-ttt`          | `sweep_ho_attempt.png`, `sweep_ping_pong.png`, `sweep_results.mat` (full tensors)      |

These exist so reviewers (and future-you) can sanity-check the simulator without re-running it. They take seconds to regenerate.

## 2. Phase 3 calibration outputs (sim parquet for KS-test)

| Subfolder                | Produced by             | Files                                                                                                       |
|--------------------------|-------------------------|-------------------------------------------------------------------------------------------------------------|
| `calibration_final/`     | `make calibrate-sim`    | `kpis_ue<id>.parquet` × 12 (~144 k rows total), `events_ue<id>.parquet` × 12, `run_metadata.json`           |
| `calibration_sweep/`     | `make calibrate-sweep`  | one `isd<I>_area<A>/` subdir per config (9 total), each holding 6 UE parquet files                          |
| `calibration_baseline/`  | smoke test (3 UE, 60 s) | smaller sample produced during initial validation; safe to delete                                           |

Schema: per-sample parquet matches `docs/schema.md` §1 (canonical KPI columns + per-row config/seed metadata). Per-event parquet matches `docs/schema.md` §2. Python loader: `analysis.calibration.ks_test.load_sim_kpis()`.

## 3. Phase 4 timelines (large, ML-ready)

Generated by `make sim TIMELINE=<name>` from `simulator/+scenarios/timelines/<name>.json`. Each timeline writes to `data/simulated/<timeline_name>/`:

| File                            | Description                                                                       |
|---------------------------------|------------------------------------------------------------------------------------|
| `samples.parquet`               | Per-UE × per-tick KPI feed (canonical schema §1 + `phase_id` / `scenario_name`)   |
| `events.parquet`                | Per-event log (HO_ATTEMPT/SUCCESS/FAIL + RLF + PING_PONG)                          |
| `ground_truth_drift.parquet`    | One row per drift event with derived `start_time_s` / `end_time_s` (timeline-global) |
| `ground_truth_anomaly.parquet`  | One row per anomaly event (timeline-global times, severity, affected UE/cell scope)  |
| `run_metadata.json`             | Timeline source path, git SHA, MATLAB version, master seed, sample/event counts    |

Schema for `samples.parquet` and `events.parquet` is canonical — see `docs/schema.md` §1–2.

**Shipped timelines:**

- `timeline_short.json` (Iter A smoke) — 3 phases × 60 s, single drift (D-2 channel swap). Repro in ~25 s on one core.
- `timeline_iter_b.json` (Iter B coverage) — 6 phases × 60 s = 360 s real time, 540 k samples, ~1.9 k HO events. Covers **all 4 drift types** (D-1 traffic, D-3 mobility, D-2 channel, D-4 reconfig) interleaved with **all 4 anomaly injectors** (A-1 RLF burst, A-2 meas glitch, A-3 cell interference spike, A-5 slow degrade). Repro in ~70 s on one core.
  Observable effects in the smoke run:
  - D-1: UE count 12 → 30 in P2; HO attempts 70 → 167.
  - D-3: HO attempts 70 → 207 (3× faster boundary crossings).
  - D-4: TTT 1024 ms collapses HOSR (18/54 successes) and triggers 44 RLFs → demonstrates value of drift-aware reconfig detection.
  - A-1: 18 extra RLFs concentrated on the 3 targeted UEs in window.
  - A-2: targeted UE RSRP `std = 0` over the freeze window (flat-line).
  - A-3: targeted cell SINR median dropped 12.9 → 2.3 dB (matches the −10 dB injection).
  - A-5: targeted UE net −9 dB over a 60 s ramp at −0.15 dB/s.
- `timeline_medium.json` (Iter C production) — **30 phases × 60 s = 1 800 s** real-time-equivalent, **22 baseline phases**, **8 drift phases** (2 of each D-1..D-4), **40 anomaly instances** (10 of each A-1, A-2, A-3, A-5). `carry_over_ues=true` so UE positions persist across phases for realistic per-UE drift trajectories. Generated deterministically by `python -m tools.gen_timeline` (`--rng-seed 42`). This is the primary input for Phase 5 Iter B (PR-AUC + bootstrap CI per anomaly type).

## 4. Phase 4 Iter C: static config-perf sweep

Generated by `make sweep-static` → `data/simulated/sweep_static/`:

| File                                  | Description                                                                                          |
|---------------------------------------|------------------------------------------------------------------------------------------------------|
| `sweep_config_perf.parquet`           | 360 rows = TTT (3) × hyst (4) × A3-offset (3) × seeds (10). One row per simulation; columns = controlled knobs + ADR-15 mobility KPIs (HOSR, HOFR_rate, RLF_rate, ping_pong_rate, RSRP/SINR/RSRQ p10/p50/p90). |
| `sweep_metadata.json`                 | Grid definition, seeds, MATLAB version, git SHA, wall-clock per run.                                  |

This is the training matrix consumed by the Phase 8 surrogate model. Repro in ~10 min on 16 workers via parfor.

**Authoring a timeline.** Anomaly `t_start_s` / `t_end_s` in the JSON are phase-local (start at 0 inside each phase) — the builder rewrites them to timeline-global seconds when emitting `ground_truth_anomaly.parquet`. Drifts are declared per phase pair (`phase_id_start`, `phase_id_end`) and time bounds are derived from phase durations. Production timelines are built parametrically by `tools/gen_timeline.py` (see `--help`); the hand-authored Iter A/B timelines remain checked in as reference fixtures. See `docs/scenarios.md` for the full schema.

## Reproducing

```bash
make demo demo-ho sweep-ttt        # all Phase 1/2 illustrations (~1 min)
make calibrate                     # Phase 3 sim parquet + KS-test (~25 s)
make calibrate-sweep               # Phase 3 3×3 tuning sweep + heatmap (~30 s)
make sim TIMELINE=timeline_short    # Phase 4 Iter A 3-phase smoke timeline (~25 s)
make sim TIMELINE=timeline_iter_b   # Phase 4 Iter B 6-phase full-coverage timeline (~70 s)
make sim TIMELINE=timeline_medium   # Phase 4 Iter C 30-phase production timeline (~7-10 min serial)
make sweep-static                   # Phase 4 Iter C 360-run config-perf sweep (~10 min on 16 workers)
make gen-timeline-medium            # Iter C: regenerate timeline_medium.json from the parametric generator
```
